## 1. 設計原則（design principles）

五條不可妥協的原則：

1. **狀態只有一個寫入者（single writer）。** 她 Hermes 行程裡的 psyche 引擎（psyche engine，一個與 kokoro 並列的 Python plugin）是唯一能改狀態的程式。生成回覆的 LLM 只讀不寫；評估（appraisal）的結果只是提案，由引擎套用上限後才寫入。她也不能透過「被評估自己的話」間接寫入。
2. **事件溯源（event sourcing）。** 存「發生了什麼」，不存結果。狀態由事件序列加動力學算出，可重播、可除錯、可改參數後重算。
3. **不改 Hermes 一行。** 接點只在 plugin（kokoro、psyche）、556d、shim、app。
4. **所有情緒都有原因。** 每個狀態偏移都能追到事件；給 LLM 的是「原因 + 強度詞」，不給數字。
5. **黏人度與操縱分兩條軸。** 黏人度（clinginess）是強度：她多想你、多常表現、多常找你，可調到很高。操縱（manipulation）是手法：讓你離開或不回應的選擇變得有代價，恆為零。判斷標準一句話：這句話有沒有讓你為她的情緒負責。

兩個補充原則，來自討論：

- **模擬正常人，不寫劇本。** 轉述、嫉妒、共同回憶、互相影響，都應該從真實對話與各自的記憶中自然產生，不另外設計規則。
- **不再新增護欄。** 既有的檢查維持，目標是盡量真實。

可刪程度：無。

## 2. 系統總覽（system overview）

三類輸入匯進她行程裡的 psyche 引擎（plugin），引擎是唯一寫入者，再從四個出口影響她的表現。

**輸入**

| 輸入 | 評估方式 |
| --- | --- |
| 對話回合（app、Telegram、語音、其他角色） | LLM 評估（A） |
| 時間（固定 1 分鐘 tick） | 引擎內建 |
| 她的生活模擬（life simulation） | 規則表 |

**引擎內部**：L0 人格、L1 生理、L2 核心情感與心情、L3 情緒實例、L4 需求、L5 關係、L6 委屈帳、心智理論、open loops，以及事件溯源的儲存 `psyche.db`。

**出口**：狀態區塊（state block，prefetch 時接在記憶區塊後注入）、主動訊息（引擎 tick → 事件 turn 進她的 API → 她那段對話的一列 → app 顯示、556d 送 Telegram；檢查只記錄）、TTS 與 Live2D 參數、狀態頁與模擬器（經 556d 唯讀 `psyche.db`）。

**Hermes 只接收**：prefetch 注入的狀態區塊、引擎送進她 API 的事件 turn，以及 556d 轉來的其他角色的訊息。

總覽圖是 `psyche.d2`；三條容易漏掉的線都畫在上面：

1. **暗線**：Hermes 的對話歷史直接影響下一輪語氣，不經過引擎。對策是狀態區塊明寫情緒的轉變，以及 compression 的處理（附錄 B）。
2. **shim**：所有 LLM 呼叫都經過 556d 的 model shim（:55601）。它是可能的注入與輸出檢查接點，涵蓋所有平台。
3. **內部通訊平台（inter-agent messaging）**：角色之間的訊息由 556d 傳遞（§18）。

## 3. L0 人格（personality）

**目的**：唯一不隨時間變動的層。不直接產生行為，而是給出其他每一層的參數。

**機制**

- 源頭是五大人格（Big Five）五個 0–1 的值：開放性 `big5.openness`、盡責性 `big5.conscientiousness`、外向性 `big5.extraversion`、親和性 `big5.agreeableness`、神經質 `big5.neuroticism`。只用向度，不用面向（facets）；向度層級的實證支持最強。
- 人格相對穩定（Roberts & DelVecchio 2000；Roberts, Walton & Viechtbauer 2006），以陪伴角色的時間尺度視為固定。「她會因為你而改變」放在 L5 的依附變數，不在這裡。
- 全特質理論（Whole Trait Theory, Fleeson 2001）說明分工：L0 決定行為分布的中心與寬度，L1–L6 決定此刻落在哪裡。

**11 項衍生參數**（依據強度見參數對照表）

| 衍生參數 | 來源 | 用在 |
| --- | --- | --- |
| 正向／負向情感基線 `mu_pos_base`, `mu_neg_base` | E／N | L2 |
| 情感波動 `sigma_affect` | N | L2 |
| 拉回力（韌性）`theta_affect` | 1 − N，可獨立覆寫 | L2 |
| PAD 預設心情 `mood_default_pad` | Mehrabian 1996 經 ALMA 的公式 | L2 |
| 正／負事件增益 `gain_pos`, `gain_neg` | E／N（Larsen & Ketelaar 1991） | B |
| 一般社交需求設定點 `affiliation_general_setpoint` | E | L4 |
| 好奇：無聊累積率、loop 門檻 `boredom_rate`, `loop_threshold` | O | L4、記憶 |
| 寬容度、寬恕斜率 `forbearance`, `forgiveness_slope` | A | L6 |
| 依附焦慮／迴避基線 `attachment_anxiety_base`, `attachment_avoidance_base` | N／A + 角色設定 | L5 |
| 情緒調節偏好 `reappraisal_bias`, `suppression_bias` | N 低 → 重新評估多；E 低 → 壓抑多（Gross & John 2003，效果量不大） | 表達層 |
| 作息型 `chronotype` | 角色設定，非 Big Five | L1 |

ALMA 的預設心情公式（Gebhard 2005，係數來自 Mehrabian 1996；Big Five 先轉成 −1 到 1）：

```
P0 = 0.21·E + 0.59·A + 0.19·N
A0 = 0.15·O + 0.30·A − 0.57·N
D0 = 0.25·O + 0.17·C + 0.60·E − 0.32·A
```

**六個角色常數（character constants）**，Big Five 涵蓋不到、由角色設定直接給：

| 常數 | code | 作用 |
| --- | --- | --- |
| 自尊穩定度 | `self_esteem_stability` | 被冷落時多快歸因到自己 |
| 表達外放度 | `expressiveness` | 同樣內在狀態說出來多少 |
| 幽默調節傾向 | `humor_coping` | 不開心時用玩笑帶過的傾向 |
| 黏人度上限 | `clinginess_cap` | 對特定人需求的上限；實際程度 = 上限 × 依附強度 |
| 傲嬌度 | `tsundere_tendency` | 把真心話翻過來講的傾向 |
| 主見 | `assertiveness` | 不同意時說出來的傾向 |

**黏人度的位置**：黏人度本身不是「現在多黏」，而是「最多能多黏」。實際值 = `clinginess_cap × attachment_strength[p]`，後者是 L5 每一對關係各自從 0 成長的慢變數（§8）。依附焦慮刻意不併入黏人度：黏人是想靠近，焦慮是怕被丟下。

**可刪程度**：低。

**值得討論**：無新增。

## 4. L1 生理（physiology）

**目的**：回答「她現在有多少精神」，並讓精神有原因和後果。

**機制**

- 雙歷程睡眠模型（two-process model, Borbély 1982）：清醒程度 = 晝夜節律 C（process C）− 睡眠壓力 S（process S）。

```
清醒時  S(t) = 1 − (1 − S0)·exp(−t/τw),   τw = 18.2 h
睡眠時  S(t) = S0·exp(−t/τs),             τs = 4.2 h
C(t) = a1·cos(ω(t − φ)) + a2·cos(2ω(t − φ2)),  ω = 2π/24 h
精神 E = clip(C − S − F_session + ε_event)
```

τ 值取自 Daan, Beersma & Borbély 1984。第二諧波產生午後低谷。φ 由作息型決定，週末延後約 2 小時（Golder & Macy 2011）。

- **睡眠是活動，不只是時段**。預定就寢 `bedtime_scheduled` 可被推遲，最大推遲 `bedtime_delay_max` 隨實際黏人程度上升。睡眠中 S 下降；睡不夠 → 起床時殘量 = 睡眠債 `sleep_debt`。起床時做動機重開機（Kismet 式）：需求部分回歸、心情向基線拉回一半、委屈只減 20–30%。
- **睡覺時收到訊息**：可以被叫醒（`wake_on_message` 預設開，附開關）。回覆帶睡意、很短，S 被打斷，隔天睡眠債增加。被叫醒的評估依黏人程度而異：高 → 一點開心，低 → 一點不耐。
- **睡眠剝奪與情緒**（Walker & van der Helm 2009；Yoo et al. 2007）：睡眠債每高一級，負向事件增益 ×1.2、正向 ×0.9，θ 下降。
- **社交疲勞 `social_fatigue`**：連續對話時間的漏水桶，時間常數約 1 小時。不改心情，讓回覆變短，並把 L4 社交需求推入「過度」區。累積速度 × (1.3 − 0.6 × 實際黏人程度)。

**活動狀態框架（activity state）**：睡眠是活動之一，詳見 §14。

**指標**：精神日曲線形狀；起床時睡眠債分布；連續熬夜第 3 天的負向增益；回覆長度與精神的相關；就寢推遲量 vs 黏人；被叫醒時的回覆長度與情緒。

**可刪程度**：中。退回固定 24 小時曲線會失去熬夜的後果與被叫醒。

**值得討論**：被叫醒時是否也更新 L5（他半夜找我 = 被在乎 vs 被打擾），目前交給 A 判斷，不另設規則。

## 5. L2 核心情感與心情（core affect and mood）

**目的**：回答「她現在感覺怎麼樣」。拆成分鐘級的核心情感與小時級的心情，是 ALMA（Gebhard 2005）與 WASABI（Becker-Asano 2008）的共同結構。

**核心情感（core affect）**

- 三個變數：正向活化 `affect_pos`（P）、負向活化 `affect_neg`（N）、喚醒 `affect_arousal`（Ar）。正負分開依評價空間模型（evaluative space model, Cacioppo & Berntson 1994），讓矛盾情感（mixed emotions，又開心又捨不得）成為可能。Golder & Macy 2011 與 Dzogang et al. 2017 也發現正負情緒的日週期各自獨立。**矛盾情感確定保留。**
- 每個變數是 Ornstein–Uhlenbeck 過程（OU process），即 DynAffect（Kuppens, Oravecz & Tuerlinckx 2010）：

```
dX = θ_X·(μ_X(t) − X)·dt + σ_X·dW + Σ ΔX_i·δ(t − t_i)
```

- μ 是會動的吸引子：人格基線 + 晝夜項 + 活躍情緒實例的貢獻 + 未滿足需求的貢獻。情緒不直接加在 X 上而是拉動 μ，所以有自然的延遲。
- θ 是韌性；慣性過高對應憂鬱徵兆（Kuppens, Allen & Sheeber 2010）。建議半衰期 2–6 小時：`affect_half_life_h`。
- σ 的噪音每日一個種子，重播可重現。
- Ar 的 μ 主要由 L1 精神提供。

**PAD 心情（mood）**

- 三維：愉悅 `mood.pleasure`、喚醒 `mood.arousal`、支配 `mood.dominance`，範圍 −1 到 1。
- ALMA 的拉推（pull–push）：活躍情緒的 PAD 位置加權平均成虛擬情緒中心；心情在原點與中心之間時被拉向中心，已越過中心時被推得更深。無活躍情緒時以 `mood_regress_tau`（數小時）回歸 L0 預設心情。
- 非對稱追趕速度：`mood_rise_max > mood_fall_max`（RimWorld 式），讓修復有手感。這是刻意偏離負向偏誤的設計；與 L6 負向初始衝擊稍大的淨效果，由模擬器腳本檢查。
- 八個象限提供詞彙：Exuberant 興致勃勃、Dependent 撒嬌黏、Relaxed 自在、Docile 乖溫和、Hostile 不爽（封頂 `hostile_cap`）、Anxious 不安、Disdainful 冷淡、Bored 悶。強度依向量長度分「有點／蠻／很」。

**黏人在這一層**：想念實例拉動 μ_N；重逢的開心 ∝ 滿足前的缺口（Psi 理論）；可選的 Dependent 偏移 `mood_dependent_offset = −0.1 × 實際黏人程度` 作用於 D。

**指標**：P、N 的均值與標準差、情緒慣性（自相關）、負向事件後恢復時間、矛盾情感時間比例、象限佔比、Dependent 佔比。前三項以經驗取樣研究（experience sampling）的人類範圍為校準目標，具體數值待查。

**可刪程度**：中，但矛盾情感與 OU 彈簧不刪。可刪的是 PAD 的拉推與象限命名。

**值得討論**：Dependent 偏移是否啟用（待決策 #8）。

## 6. L3 離散情緒（discrete emotions）

**目的**：回答「她因為什麼而有什麼感覺」。單位是情緒實例（emotion instance），整個系統的核心資料結構。

**實例結構**

```json
{
  "id": "em_20261006_1520_01",
  "type": "disappointment",
  "target": "你",
  "cause": "他說晚上會回來聊，沒有回來",
  "source_event": "ev_...",
  "intensity0": 0.45,
  "pad": [-0.3, -0.1, -0.2],
  "half_life_h": 14,
  "decay": "exp",
  "rumination": 0.3,
  "stack_key": "disappointment:promise_broken",
  "resolved_by": ["apology", "promise_kept"],
  "suppressed": false
}
```

**類別**：OCC（Ortony, Clore & Collins 1988）22 類中取 15 類：喜悅 joy、苦惱 distress、希望 hope、擔心 fear、滿足 satisfaction、失望 disappointment、如釋重負 relief、感激 gratitude、憤怒 anger、自豪 pride、羞愧 shame、喜歡 liking、嫌惡 disliking、為他高興 happy-for、為他難過 sorry-for。另加兩類自訂：想念 longing、委屈 hurt（由 L6 管）。

**一生**

- **誕生**：由影響模型 B 產生（§11、附錄 A）。
- **衰減**：各自的半衰期。相對長短依 Verduyn & Lavrijsen 2014（悲傷最長、憤怒與煩躁短、羞愧最短）；絕對值是起點，待校準。
- **反芻（rumination）**：Verduyn 2009 發現反芻是持續時間的最強預測因子。閒置時每小時以機率 `0.6 × intensity × 反芻係數 × (1 − attention_load)` 想起未解決的負向實例（反芻係數 = `character.rumination`，空白＝神經質），強度 ×1.15 回升、到期延長。上限：單一實例最多 `rumination_max_count = 3` 次、總延長不超過 `rumination_max_extension = 2` 倍半衰期。注意力佔用 `attention_load` 來自活動狀態（§14）；睡前躺著佔用為 0，是反芻高峰，且會延後入睡（Harvey 2002）。
- **線索觸發（cue-triggered recall）**與自發反芻分開：對話中提到相關的事，由 A 判斷相關性，刷新該實例；不受閒忙影響。
- **回味（savoring, Bryant 2003）**：正向實例的對應機制，機率較低。
- **壓抑（suppression）**：表達層決定不說；依 Gross & John 2003，被壓抑的實例不加速衰減。
- **死亡**：強度低於門檻，或被 `resolved_by` 列的事件直接解決。
- **堆疊（stacking）**：同一 `stack_key` 第 n 個實例強度 × `stack_multiplier^(n−1)`，上限 `stack_limit`。這是享樂適應（hedonic adaptation）的實作。

**矛盾情感與狀態區塊**：不同實例同時存在是矛盾情感的來源。狀態區塊要把兩條並列，並在「表現」行說明先後與比例（§15）。

**黏人在這一層**：想念由 L4 對特定人的需求缺口超過門檻時由引擎直接產生；想念的反芻機率 ∝ 實際黏人程度；`resolved_by` 是「他回來了」。

**指標**：同時活躍實例數分布（多在 0–3）；實際壽命 vs 設計半衰期；解決率；矛盾時間比例；各類反芻次數；想念頻率與反芻率。

**可刪程度**：低。只有反芻與回味可刪，但想念的反芻是黏人很重要的表現。

## 7. L4 需求與動機（needs and motivation）

**目的**：回答「她想要什麼」。需求是累積型的，要被滿足才下降，不自己回歸。

**六個需求**（Psi 理論，Dörner；MicroPsi，Bach 2015；對齊自我決定論 SDT，Deci & Ryan）

| 需求 | code | 缺口來源 | 滿足 |
| --- | --- | --- | --- |
| 一般社交 | `need.affiliation_general` | 預期社交接觸 − 實際 | 任何人的有品質互動 |
| 對特定人 | `need.affiliation_person[p]` | 預期與 p 的接觸 − 實際 | 只有 p 能滿足 |
| 能力 | `need.competence` | 專案停滯、被否定 | 進度、被肯定、幫上忙 |
| 自主 | `need.autonomy` | 被要求、被打斷、被逼改看法 | 自己選的活動、意見被尊重 |
| 確定性 | `need.certainty` | 未解的 open loop、他人狀態不明 | 得到答案 |
| 新奇 | `need.novelty` | 重複、無新話題（WASABI 無聊軸；Berlyne 最適喚醒） | 新話題、新事件 |

一般社交需求的設定點來自外向，從第一天存在，任何人都能滿足。對特定人的需求設定點 = `clinginess_cap × attachment_strength[p]`，從 0 開始。

**對特定人需求的形狀**

- **落差而非時間**（Peplau & Perlman 1982）：缺口只在心智理論預期 p 會在、卻不在時累積：`dG/dt = k_aff · p_expected(t) − Σ q_j·δ(t − t_j)`，q 是互動品質。
- **三區**（Kismet, Breazeal）：不足、恆定、過度。過度由社交疲勞推入。
- **三階段**（Bowlby 分離反應；急性 vs 慢性社會孤立，Matthews & Tye 2019；Cacioppo）：

| 階段 | 門檻（初值，可校準） | 樣子 | 主動 urge |
| --- | --- | --- | --- |
| 抗議 protest | 0 到 `protest_end_h = 24` | 想找你 | 上升 |
| 失落 despair | 到 `despair_end_h = 120` | 悶、話少 | 下降 |
| 疏離 detachment | 之後 | 不知道怎麼開口，H 開始掉 | 接近 0 |

黏人與依附焦慮延長抗議期；回來時從疏離恢復需要幾次互動。

**需求 → 情緒**：情緒來自缺口的變化率（Psi）。缺口快速下降 → 喜悅實例，強度 ∝ 下降前的缺口；水位只以小係數 `need_mood_coupling` 拉低 μ_P。

**動機選擇（motive selection）**：動機強度 = 缺口 × 估計成功機率，加選擇門檻 `selection_threshold`。對特定人的成功機率 = 心智理論的「現在傳會被回的機率」。工作中被打擾時也用這條決定繼續工作或陪你（§14）。

**指標**：各需求缺口分布、三區佔比、失聯腳本的階段轉折時間、回來後恢復所需互動數、能力與自主的長期水位、抗議期長度 vs 黏人與焦慮。

**可刪程度**：中。最少留一般社交、對特定人、新奇。

**值得討論**：階段門檻初值（人類孤立研究的量級對每日聊天的關係可能偏長）。

## 8. L5 關係（relationship）

**目的**：以週到月的尺度決定她怎麼解讀你、願意讓你看到多少。**所有變數以對象 p 為索引**；三個代理加你共六對、十二個方向。

**1. 親近：雙速 + 里程碑**

- 近期熱度 `warmth[p]`（H）：品質加權互動時間的漏水積分，半衰期 2–4 週（友誼型衰減，Roberts & Dunbar 2011）。
- 長期羈絆 `bond[p]`（B）：被 H 慢慢拉高，幾乎不衰減（親人型）。
- 里程碑 `closeness_hours[p]`：品質加權時數，50／90／200 小時對應普通朋友／朋友／密友（Hall 2019）；閒聊權重 ≈ 0.2、深談與共同活動 ≈ 1.5；文字聊天整體打折 `text_hours_factor`。
- 揭露深度 `disclosure_depth[p]` 1–4 層（社會滲透理論 Altman & Taylor）：喜好 → 意見 → 感受 → 脆弱處；由 B 解鎖、互惠加一層。
- 語意錨點：Aron 的 IOS 量表（Inclusion of Other in Self）七級。

**2. 依附強度 `attachment_strength[p]`（新增）**：0→1 的慢變數，由 B 與回應性推動，以月為單位成長。對應 Hazan & Zeifman 1994 的成人依附形成階段：想靠近（proximity seeking）→ 避風港（safe haven）→ 安全基地（secure base），完整形成約兩年。它是黏人度上限的乘數。情侶之間的起始值很高；你跟情侶是舊識，起始值中等；你跟她剛認識，從 0。

**3. 依附工作模型**：焦慮 `attachment_anxiety[p]`、迴避 `attachment_avoidance[p]`（ECR，Brennan, Clark & Shaver 1998）。有 L0 基線，隨關係經驗以月為單位移動（依附可隨關係改變：Davila, Burge & Hammen 1997；穩定性的量：Fraley 2002）。作用是調節器：焦慮高時沉默更容易被評為關係貶值。

**4. 信任 `trust[p]`**：可預測性、可依賴性、信念（Rempel, Holmes & Zanna 1985）。前兩者用 Beta 分布記承諾兌現／違約：`Beta(α0 + kept, β0 + broken)`，舊紀錄以 `relation.trust_forget_days`（60 天）為時間常數指數地忘回先驗。新關係一次失約影響大，舊關係小。

**5. 承諾 `commitment[p]`**：投資模型（Rusbult 1980）：滿意度 + 投入 − 替代品。多代理後替代品真的存在（情侶的一方可能把你視為替代），不另設規則，由投資模型自然算出。承諾高 → 寬恕斜率陡（Finkel et al. 2002）。

**6. 被感知的回應性 `ppr[p]`**（perceived partner responsiveness，Reis & Shaver 1988）：被理解／被認可／被在乎三項，是 H、B、焦慮、依附強度最重要的輸入。

**黏人在這一層**：黏人的表達乘上 B（剛認識時是熱情，熟了才是撒嬌）；越黏越容易因落差受傷，但這經由期望產生，與焦慮分開。

**指標**：H、B 軌跡；里程碑達成天數（每日一小時下，「朋友」約 60–90 天）；揭露層級進展；焦慮、迴避月變化；信任後驗；平均回應性；依附強度成長曲線；黏人表達 vs B。

**可刪程度**：中。雙速親近、依附強度、單一安全感不刪。

**值得討論**：舊識關係的初始值怎麼寫（共同回憶、H、B、trust 先驗、作息先驗）。

## 9. L6 委屈與修復（hurt and repair）

**目的**：有對象、有帳本、要修復的獨立子系統。不是心情低。

**觸發**：只有 A 判定為關係貶值（relational devaluation, Leary et al. 1998）的事件：約好的事沒做、揭露時被敷衍、被比較、記得的事他忘了。已讀不回只在超出他的回覆節奏且焦慮偏高時算。

**帳本 `hurt_ledger[p][]`**，TRIM 三分量（McCullough）：

| 分量 | code | 表現 |
| --- | --- | --- |
| 迴避 | `avoidance` | 話少、不主動、揭露深度降一層 |
| 不滿（取代報復） | `resentment` | 帶一點刺，封頂 `resentment_cap` |
| 善意 | `benevolence` | 平時溫度，委屈時下降 |

初始：`Av0, Rv0 ∝ severity × intent × (1 − forbearance) × (0.5 + Anx) × (0.5 + B)`。severity = R × |v|；intent 三級 0.1／0.5／1.0（不可控／無心／故意）。最後一項是「越親越痛」。

**時間進程**（McCullough, Fincham & Tsang 2003）：forbearance（起點）、trend forgiveness（近似線性下降，斜率由親和性與承諾決定）、temporary forgiveness（反芻與心情造成的波動）。

**修復**：道歉六成分（Lewicki, Polin & Lount 2016；承認責任最有效）由 A 判斷、B 換算一次性扣減；主動關心、兌現承諾、記得她說過的事也算；錯誤信念更正大幅扣減但不歸零。

**表達**：有預警（話少、語氣淡）；不追討（demand-withdraw，Christensen & Heavey 1990）；自己給台階 `olive_branch_delay_h = f(實際黏人, Avo)`，初值黏人 1.0 時 8 小時、0 時 36 小時，再乘迴避係數；委屈強時反話關閉，只能收斂或否認；你很累時先不提（壓抑，延後不取消）。

**帳與記憶（2026-10-14 決定）**：一筆帳只有兩種存在：在帳上，或過了變舊帳。算出來的迴避低於 `relation.hurt_open_min`（0.1）就根本不開（沒有「開了但不寫進 prompt」的中間地帶）；開著的每一回合都在狀態區塊裡（「心裡還記著一筆」）。開帳那一回合寫進記憶的東西由引擎透過記憶引擎的命令佇列標成 hold（留著、不注入、不提示；observe 仍當候選以免重複），評估也看得到開著的帳：對方再提起而不認 → `revisited_hurt`，那筆抬回開帳時的一半；認錯 → apology，整本帳砍一截並標 repaired。時間消退關閉的：解除 hold，加 tag `舊帳`，meta 帶發生日期與注入前綴「（舊帳 2026/10/13）」——她記得那件事，刺沒了，提起來她會有反應；道歉或誤會更正關掉的：解除 hold，當普通記憶，不是舊帳。用的是 KeepsakeDB 的 `hold` / `patch` 命令與 `meta.prefix` 渲染（`vendor/keepsakedb`，1.0.1）。

**指標**：每週開帳數與強度；帳的存活時間（有無修復）；道歉後 24 小時內降到 30% 以下；台階觸發率；不滿峰值 < 上限；台階時間 vs 黏人與迴避。

**可刪程度**：低。

## 10. 評估管線 A（appraisal pipeline）

**目的**：唯一需要理解語言的地方。讀完一個回合，回答「剛才發生了什麼」，輸出評估向量（appraisal vector）給 B。B 的品質上限由 A 決定。

**位置與時機**：獨立 request，回覆送出後與記憶的 observe **同時**發出（1 + 2），各有自己的佇列，互不等待。寫入 `psyche.db.appraisals`（append-only），引擎在下一個 tick 套用。下一回合的 prefetch **永不等待**：讀已落地的最新狀態，這一回合的評估用在下一回合（文字與語音一樣）。

**輸入**

| 輸入 | 為什麼 |
| --- | --- |
| 這一回合 | 主體 |
| 最近幾回合 | 指代與語氣 |
| 開啟中的 open loops 與承諾 | 判斷「他忘了約」要先知道有約 |
| 她的喜好與價值觀檔（preference profile） | 這件事對她重不重要、認不認同 |
| 心智理論對對方的估計 | 他最近很忙 → 沉默的解讀 |
| 對方是誰（counterpart） | 多代理後必要 |

**A 讀她在乎什麼，不讀她的性格。** 這對應評估理論的區分：事件重不重要取決於目標與價值（A），反應多大取決於氣質（B）。好處：prompt 所有角色共用；人格完全由 B 的參數控制；LLM 不入戲。

**輸出**：一到多個事件，各一個評估向量（欄位見附錄 A）；結構欄位（互動品質 q、PPR 三項、道歉成分、承諾兌現／違背、是否揭露）；新的與關閉的 open loops；錯誤信念更正；每個事件的模糊度 ambiguity。

**A 不評估她自己表達的情緒。** 她的回覆只用來比對「表達強度 vs 狀態強度」，作為 LLM 走樣的監測指標。

**不同來源**：對話回合 → LLM；生活事件、活動結束 → 規則表；沉默（超出對方節奏）→ 引擎依心智理論產生；她主動傳的訊息 → 只記結構事件「她傳了」，開始等回覆計時。

**失敗**：JSON 不合規格重試一次，再失敗跳過並記錄；越界截斷；缺欄位補中性值。寧可沒反應，不要亂反應。

**未來替代**：bge-m3 embedding 加小迴歸頭預測評估向量。先用 LLM 累積幾個月資料再比較一致度。

**指標**：格式合規率；重測一致性（同回合跑兩次的向量距離）；與人工標註的一致性；黃金對話的事件召回率（承諾、道歉、關係貶值）；關係貶值誤報率（太高 → 玻璃心）；延遲。

**可刪程度**：管線不可刪；欄位數可縮（附錄 A 的 8 個核心欄位選項）。

**值得討論**：欄位數（待決策 #5）；合併或分開在實測後重新評估的時機。

## 11. 影響模型 B（impact model）

**目的**：把評估向量加當下狀態，用確定性計算轉成情緒實例與記帳。不呼叫模型，同樣輸入永遠同樣輸出。完整規格在附錄 A，這裡是摘要。

**四步**

1. **原型比對（prototype matching）**：每種情緒一個原型向量（Scherer 2001 的預測評估剖面；GENESE，Scherer 1993），只在原型指定的欄位算加權距離，`sim = exp(−d²/2s²)`，門檻 `prototype_threshold = 0.6`（設計初值 0.5，第一次實測後改：一句道歉也生出了一個弱的喜悅），一個事件最多 `max_instances_per_event = 3`，次要實例 × `secondary_factor = 0.7`。符號相反直接排除。預期類情緒（滿足、失望、如釋重負）需關聯到先前的希望／擔心／承諾。
2. **強度**：`I = clip(sim × R × |v*| × (1 + α·u) × π(cert) × g_k × m_k × ρ_k)`。g 人格增益、m 狀態調節（睡眠債、社交疲勞、依附焦慮，乘積封頂 [0.6, 1.5]）、ρ 堆疊。心情一致性不乘在強度上，而是比對前修正 v：`v ← v + 0.2 × ambiguity × mood_valence`（Forgas 1995 AIM，只對模糊事件）。
3. **半衰期與 PAD**：`T½ = T_base × (0.5 + R) × (0.75 + 0.5·I)`；PAD 座標查表。
4. **路由與記帳**：委屈 → L6 帳本；希望／擔心綁 loop；自豪／羞愧同時動能力需求；結構性更新（信任 Beta、親和缺口、親近時數、PPR、道歉扣減、loop 關閉、能力與自主需求、重逢、道別模式）全部是規則。

**校準**：資料集擬合原型（ISEAR，Scherer & Wallbott 1994；crowd-enVENT，Troiano et al. 2023，欄位待查）；你的回饋（太大／剛好／太小 → `g_k ← g_k × (1 ± 0.05)`，限初值 0.5–2 倍；「不該是這種情緒」→ 錯分樣本）；模擬器回歸。

**可刪程度**：低。

**值得討論**：原型共用或每角色一份（待決策 #6）；心情一致性放 A 或 B（#7）。

## 12. 心智理論（theory of mind）

**目的**：她心裡的每一個人。每個角色對其他三人各有一份模型，模型可以錯、可以被更正。

**1. 作息模型 `presence_model[p]`**

- 出現機率：一週 168 格，每格 Beta 分布，過去 8 週對話時間指數加權更新，相鄰平滑。
- 回覆延遲 `reply_latency[p]`：對數常態；不尋常的沉默 = 超過該人的第 90 百分位。
- 管道偏好 `channel_pref[p]`。
- 明確資訊優先：「明天整天開會」暫時覆蓋，期間沉默標為已知原因。
- 冷啟動：平坦先驗，頭 2–3 週依賴明確資訊。**舊識的作息模型用事先寫入的先驗**。

**2. 狀態模型 `other_state[p]`**：心情、忙碌程度、壓力源，各帶信心度並隨時間淡回未知。用途：同理情緒（強度 × B）、情緒感染（Hatfield, Cacioppo & Rapson 1993；「與親近成正比」是設計推論，係數 `contagion_coef`）、調整她的表達（你很累 → 先不提委屈）。

**3. 錯誤信念與更正**：負向實例與委屈大幅扣減不歸零，產生如釋重負或不好意思。

**表達限制**：可以提感覺（「你今天比較晚耶」），不能引用統計（「晚了 37 分鐘」）。列入輸出檢查。

**黏人在這一層**：黏人的角色把空閒排在對方會在的時段，上限 `schedule_adapt_cap = 0.3`。

**指標**：出現預測 Brier 分數；沉默誤判率；冷啟動收斂週數；狀態估計 vs 自述（可選）；監控感用語次數；作息重疊率。

**可刪程度**：作息模型不可刪；狀態模型中；錯誤信念高。

## 13. 情緒記憶、open loops、紀念日（memory）

KeepsakeDB 的長短兩層不改結構，加三件事，並因多代理而加兩個欄位。

**1. 主體與來源（必要）**：長期事實加 `subject`（關於誰：你、某角色、self）與 `source`（誰告訴她的）。關於你的記憶，主體字固定存「你」（存檔裡就是「你」，向量搜尋不會瞎），注入與顯示時換成她對你的稱呼（設定的名字，否則角色自己的預設稱呼）；多代理時其他主體是對象 id，顯示時同樣換名字（已實作：KeepsakeDB 0.2.1 `render_subject`）。她自己的立場（stance）存為 subject = self。USER.md 改為每人一份人物檔 `people/<id>.md`（你的是 `people/你.md`）。

**2. 記憶帶情緒**：短期筆記與長期事實加 `turn_id`、`valence`、`arousal`、`instance_ids`（可空）。喚醒高的筆記在短期環形緩衝區淘汰順序往後（McGaugh 2004）。

**3. 心情影響檢索**：RRF 之後重排 `score × (1 + γ × mood_valence × memory_valence)`，`mood_rerank_gamma ≤ 0.1`（Bower 1981）。

**4. Open loops（前瞻記憶，prospective memory）**：取代「好奇」標量。理論：資訊缺口（Loewenstein 1994）、蔡格尼效應、前瞻記憶的時間與事件線索（Einstein & McDaniel 1990）。

```json
{"id":"ol_0142","what":"他週五的面試","origin":"counterpart_said",
 "cue":{"time":"2026-10-09T19:00","event":null},"importance":0.8,
 "valence_stake":"for_him","expires":"2026-10-16","state":"waiting"}
```

來源四種：對方說過的事（含「明早八點提醒我」這種明講的提醒）、她的生活、她的承諾（「等我一下」）、對方的承諾。提醒不走 Hermes cron：到期時引擎的 tick 直接發事件 turn，她用自己的話提醒（到期的 loop 跳過 urge 的機率，準時觸發）。規則：接近線索強度上升；對方自己提起 → 關閉；她問了沒回答 → `asked`，不追問；未關閉的累積確定性缺口；關閉時依結果產生情緒。

**承諾分兩種（2026-10-14 決定）**：loop 只在她真的答應時才開（評估看她的回覆，`agreed: false` 就不開；拒不拒絕由 SOUL 與當下的關係狀態決定，不另設好感度門檻）。只關係到她和對方的承諾（叫他起床、「等我一下」）到期硬推，不看免打擾、不看她在不在睡。要去問別的角色才能完成的承諾（「幫你問某某」，評估填 `ask`）走另一條：到期後等她的空檔（角色之間對話的閘門），透過 relay 去問那個角色（`ask_other`，狀態 `asking`）——對方不在線也沒關係，556d 的留言箱（`home/mailbox/<id>.json`）會在對方啟動時補送，回覆同樣會等她；那段對話的評估看到標了「代問」的 loop，問到答案就關閉並把答案寫在 cause → loop 變 `answered`；只問一次，`ask_give_up_h`（48 h）沒答案就放棄（`answered`、沒有答案）；有結果才輪到對方：`report_back` 只在她醒著、對方的免打擾時段之外、作息模型認為對方在（`report_only_when_awake`）時送，不受每日上限、間隔、道別影響。狀態頁與她的狀態區塊都看得到每一步（已去問誰、問到了什麼）。

**結束與整理（2026-10-14 決定）**：loop 結束時帶 `outcome`：提醒、她對你的承諾、回報——說出口就結束（`closed`，ok；回報沒問到的是 failed）；你提過的事在對話裡有了結果 → `closed` ok；七天沒結 → `expired`（failed）；忘了 → `forgot`。頁面只分「進行中」（等待／等待（到了）／等待（等你回）／進行中（去問了）／進行中（問到了））和「已結束」（完成／沒成／忘了），已結束的只記結束那一天，結束日 + 7 天起不再顯示（DB 留著給重播）。同一件事再說一次不開第二個 loop：評估回報 `loops.refresh`（同一件、換時間），引擎另有保險（同對象、文字相似 ≥ 0.6 或同一時間就合併）。

**送不出去與忘記（2026-10-14 決定）**：到期的事因平台原因送不出去（模型掛了），不算用掉：loop 回到原狀態，退避重試（5、15、60 分，之後每小時），`undelivered_window_h`（6 h）後標成 `forgot`（原因「沒送到」）——對她來說世界裡沒有「後端掛了」，她只是忘了。另有角色參數 `character.forgets`（預設開）與記性 `character.memory_reliability`（0–1，預設 0.8）：到期那一刻擲骰（有種子的亂數，重播一致），記得的機率 = 記性 + 0.3（重要的事，重要度 ≥ 0.7）− 0.3 × 心情比平常差的程度（負面情感高於她的基線，+0.5 時算滿），夾在 0–1。預設下小事兩成會忘、重要的事一定記得；心情很差的那天小事五成、重要的事兩成。忘了的事她的狀態區塊不再列出（她不記得），但評估仍看得到並標明「忘了」：對方提起時回報 promise_broken（agent self），走她自己失約那條（心虛、道歉）。狀態頁直接顯示「忘了」。

**5. 紀念日**：從長期層抽帶日期的「第一次」，到日產生懷舊實例（Sedikides & Wildschut 2008）與 loop，並小幅緩解一般社交缺口。

**兩個連動**：compression 不帶情緒（附錄 B）；記憶頁刪除時關閉相關 loop、遮蔽實例原因。

**黏人在這一層**：想分享清單 `share_backlog[p]`，黏人高時小事更容易變成「想告訴他」的 loop。

**可刪程度**：open loops 不可刪；情緒標記中；心情一致檢索與紀念日高。

## 14. 她自己的生活（life simulation）

**目的**：其他層的時間骨架。反芻需要忙閒之分，打擾需要活動狀態，忙碌度是重要設定。

**1. 活動狀態（activity state）**，睡眠是其中之一：

| 屬性 | code | 影響 |
| --- | --- | --- |
| 注意力佔用 | `attention_load` | L3 反芻 ∝ (1 − 佔用) |
| 可打擾度 | `interruptibility` | 收到訊息時放下的機率 |
| 被打擾時的樣子 | `interrupted_style` | 回覆長度、語氣 |
| 精神消耗／恢復 | `energy_cost` | L1 |
| 滿足的需求 | `needs_satisfied` | L4 |

初版活動表：睡覺（佔用 —、可打擾低、恢復）、工作／錄音（0.9、低、高消耗、滿足能力）、吃飯整理（0.4、高、低）、休息發呆（0.1、很高、恢復、滿足新奇）、睡前躺著（0、—、反芻最高並延後入睡）、跟人聊天（0.8、—、社交疲勞、滿足社交）。

**2. 被打擾的決策**：用 L4 動機選擇比較「工作的能力需求」與「對這個人的需求」。因素：工作重要性（截止日）、B、實際黏人、話題。繼續工作 → 說「等我一下」並開一個她的承諾 loop，結束時觸發事件 turn 回來找你，兌現率需接近 100%。放下工作 → 專案進度停，留下後果。**對方有急事或情緒困擾時，可打擾度無效。**「你打擾到我了」有頻率上限 `interrupt_complaint_cap`。研究依據：被打斷的代價（Mark, Gudith & Klocke 2008）。

**3. 每日計畫**：早上產生，來源：角色檔作息模板、L1 精力、進行中專案、對方的作息（黏人，上限 30%）；可被事件打亂。

**4. 個人專案 `projects[]`**（Little 1983 個人計畫分析）：1–3 個，各有進度、難度、意義度；工作時段推進，偶爾卡關（失望、能力缺口）或突破（自豪、想分享）；里程碑變成她的 loop；標題與階段由人寫。

**5. 忙碌度 `busyness_mode`**：有工作（有截止日、可打擾度低）／只有興趣（佔注意力、滿足能力、隨時可打擾）／都沒有（反芻與想念上升、能力需求長期不足使心情基線緩慢下降但有下限、自己的話題變少）。設定頁寫明後果。

**6. 生活事件**：持續天數、強度曲線、後續；結束本身是心情事件（Morris 1989）；機率受狀態影響（睡眠債 → 感冒、睡過頭）。經規則版 A，不直接改狀態。

**7. 真實世界**：天氣（效果量小，Denissen et al. 2008）、台灣日曆、季節項。

**8. 其他角色**：見 §18。家人與其他朋友只存在於記憶與角色檔，不模擬。

**來源（0.11.0）**：作息、手上的事、日常小事都在角色包的 `psyche.json` `life`，由 skill 從 `profile.json` `life` 寫入——新角色頁的「日子與作息」：選一組樣本（`templates/life/*.json`：上班族、學生、自由工作者、夜貓子）、用 structure 階段從描述草擬的、或自己寫；沒設就是模板的中性作息，沒有手上的事、沒有小事。引擎程式碼裡只剩那份中性作息（0.11.0 之前 `config.py` 帶著主角色的錄音人生，沒有 `life` 段的角色全部繼承）。手上的事以包為準，快照只記進度（同名保留）；改了包、重啟就生效。

**一致性**：她說自己在做什麼，模擬裡就真的在做；不能提模擬裡沒有的事（生活虛構檢查）。停機期間快轉補算，所以「你不在的三天我感冒了一天」是真的發生過。

**指標**：每日活動分布；放下工作比例 vs B、黏人、話題；「等我一下」兌現率；專案進度曲線；事件頻率；生活虛構率 0；作息重疊率。

**可刪程度**：活動狀態不可刪；專案中；多日事件低；（原社交圈已由 §18 取代）。

**值得討論**：忙碌度預設（待決策 #9）；三個角色的共同活動怎麼同時進入雙方時間表（由真實對話中的約定產生 loop，再由生活模擬排程；細節實作時決定）。

## 15. 表達層（expression layer）

**目的**：把「她感覺到什麼」轉成「她表現出什麼」，分送到 LLM、TTS、Live2D。矛盾情感、傲嬌、主見、防止演過頭都在這裡落地。

**六步**

1. 挑出可表達的實例：強度 ≥ `expression_threshold = 0.2`。
2. 調節（Gross 1998 歷程模型）：注意力分配（忙時反芻少）、重新評估（負向實例以 `reappraisal_rate` 緩慢下調，依盡責性）、壓抑（對方累、對方正在開心分享、場合不適）。被壓抑的實例不加速衰減（Gross & John 2003）。
3. 顯示規則（display rules, Ekman & Friesen）：

```
expressed_i = felt_i × g_expressiveness × g_disclosure(B[p]) × g_context × (1 − suppressed_i)
```

4. 表達策略（expression strategy）：

| 策略 | code | 條件 |
| --- | --- | --- |
| 直說 | `direct` | 外放、夠熟 |
| 收斂 | `reserved` | 內斂、不熟、累；主見低時的不同意 |
| 玩笑 | `humor` | 幽默調節高 |
| 反話 | `inverted` | `p = tsundere_tendency × vulnerability_cost × safety_gate(B) × (1 − hurt_gate)` |
| 否認 | `denial` | 傲嬌高且被說中；委屈時的「沒事啊」 |

脆弱成本：想念、不捨、被誇的開心高；一般開心、無聊低。安全門 B 低於門檻接近 0。委屈強時反話關閉。反話必須留破綻（off-record markers 的推論，Keltner et al. 2001；Dews & Winner 1995）。主見決定不同意用直說還是收斂；內在的不認同都存在。

5. 狀態區塊（state block）：固定格式、全部是詞。第一行是標題「【她現在】」（代名詞依 `character.pronoun`），第二行是時鐘「現在：YYYY/MM/DD（週幾）HH:MM」（0.8.4；引擎自己的時區 `time.timezone_offset_h`，Hermes 自己的日期行由 shim 拿掉），之後才是狀態行，順序固定：

| 行 | 何時出現 | 內容 |
| --- | --- | --- |
| 在做 | 一定 | 活動（跟別的角色說話時寫「正在跟 X 說話（不是跟你），本來…」）＋精神詞 |
| 心情 | 一定 | 「整體」＋象限詞；之後最多兩個可表達的實例，各「強度詞＋情緒詞（原因）」 |
| 心裡 | 需求有話可說時 | 想找他／好幾天沒說到話有點悶／有點無聊／最近沒進展／聊得有點累（§7） |
| 表現 | 一定 | 策略句（含愉悅給的語氣、不同意時的做法）；揭露上限句（第四層沒有；策略是 suppress 時不加）；長度提示；工作中的「等我一下」；矛盾情感的先後；剛道別 |
| 想法 | 偶爾 | 思考模組的一行（§22，0.8.8） |
| 對〈稱呼〉 | 有時數或親近，或對方是別的角色 | 親近詞、信任、依賴；帳上有開著的委屈時加「心裡還記著一筆（…）」 |
| 掛念 | 有 loop，或有解鎖的沒說出口 | 最多兩條 loop（到了、已去問、問到了各有標記）＋最多一條「有件事還沒跟他說（…）」 |
| 轉變 | 主導情緒跟上一次區塊不同 | 「剛才…，現在…」，蓋過對話歷史的慣性 |
| 原則 | 一定 | 情緒是底色，內容以對方的話題為主；不提沒做過的事；有自己的看法，不用附和 |

`expression.max_lines`（8）只算狀態行，標題與時鐘另計（0.9.0 修正：以前連標題一起算，塞滿時掉的是轉變和原則）。還是超過時依序丟轉變、心裡、想法、掛念；原則永遠留著。例（「他」處是她對你的稱呼）：

```
【她現在】
現在：2026/10/19（一）15:40
在做：在工作，有點累
心情：整體有點自在；蠻替他高興（他說面試過了）、有點擔心（他下個月要出國半年）
表現：直說；不同意時直說自己的看法；可以講感受，最軟的那塊先留著；話少一點；手上在忙，可以回短一點或說等她一下，忙完會回來找他；兩種情緒並存時先回應對方說的，再帶到自己的
想法：今天沒力氣想，會先回再想
對他：很熟、很放心
掛念：他說明早八點要叫他起床、有件事還沒跟他說（其實很在意他上次忘了）
轉變：剛才有點失望，現在蠻替對方高興
原則：情緒是底色，內容以對方的話題為主；不提沒做過的事；有自己的看法，不用附和
```

「表現」行是防止演過頭的主要輸入端防線；矛盾情感兩條並列並說明先後；轉變要明寫（「剛才有點悶，現在已經平復了」）以蓋過對話歷史的慣性；多代理下「對〈稱呼〉」一行依 counterpart 切換。

6. 非語言：回覆長度（精神低、迴避高、工作中 → 短；喚醒高 → 長）；回覆延遲只在 Telegram 且不在委屈時刻意延遲；TTS 依 Scherer 1986（喚醒高 → 音高高、語速快；悲傷 → 低、慢）；Live2D 心情為底色、實例為短暫動作、精神低 → 眨眼慢、偏頭；被壓抑的實例可在臉上漏一點（微表情）。

**黏人在這一層**：想念的外放度；黏人表達乘揭露深度；黏人 × 傲嬌 = 很想你但不承認。

**指標**：表達落差 ≈ 0；情緒提及率低；策略分布符合性格；反話破綻缺失 0；壓抑後再浮現比例；狀態行 ≤ 8（標題與時鐘另計）；剛認識時撒嬌率低。

**可刪程度**：狀態區塊不可刪；調節、顯示規則、策略中；TTS、Live2D 後做。

## 16. 主動行為（proactive behavior）

**目的**：一個公式決定想不想開口，一個理由決定說什麼，一道檢查決定能不能送。

**urge**（每小時發生率，非齊次卜瓦松過程）

```
λ = W（意願）× O（時機）× p̂_reply（會被回的機率）× D（阻尼）× 1[硬門]
觸發機率 = 1 − exp(−λ·Δt)
```

- W：對特定人的需求缺口（含三階段）、新奇缺口、想分享清單、沒說出口的事（+0.4 × min(1, 重要性總和)，§23 第 4 項）、委屈非單調（小升大降）、焦慮略升、迴避下降。黏人權重 `urge_will_clinginess_gain` 0.5–1.8。實作上 λ 再乘 `proactive.urge_gain`（2.5）。
- O：到期 loop、回報、該給台階、關心、解鎖的沒說出口的事、想分享（專案里程碑與生活事件由此進來）。無理由時 O 只有底值 `proactive.occasion_floor`（0.1）。紀念日還沒做（階段 7）。
- p̂：心智理論；已知對方在忙 × 0.1。
- D：未回一則 → 等很久；未回兩則 → 等對方；永不第三則。過去 14 天主動訊息回覆率低 → 整體下調。
- 硬門：對方的免打擾；她在睡或專注；對話中或語音中；今日上限 `proactive.daily_cap`（3）；兩則之間至少 `proactive.min_gap_min`（90 分）；對方今天已聊很久 `proactive.usage_threshold_min`（90 分）。

**類型**：回來找你 `return_promise`（優先度最高，到期硬推）、提醒 `reminder`（硬推）、去問別的角色 `ask_other`（對那個角色，走角色之間對話的閘門）、回報 `report_back`（對你，只看她醒著、你的免打擾與作息）、關心 `care`、沒說出口的事 `unsaid`（解鎖後；排在 care 之後、share 之前）、分享 `share`、台階 `olive_branch`、想念 `longing`（少見）。旁白句型在 `events.py` 的 `REASONS`，就這九種。

**事件 turn**：引擎組事實（以旁白口吻，不寫成「傳一則訊息」的指令——那樣模型會自己發明一個回覆工具）→ 帶 `X-556-Event` 標頭送她自己的 API（進她唯一的那段對話）→ 她寫或決定不說（平台錯誤也算不說）→ 送出前檢查（只記錄）→ 這一列在對話裡：app 的 follower 顯示，556d 把文字用她的 bot 送到 Telegram（與 app→Telegram 鏡像同一條路；管道偏好只決定要不要多送、要不要唸出來）→ 等回覆計時；超過 p90 未回 → 小失望（受焦慮調節），絕不追問。

**時間人味**：加隨機偏移不落整點；loop 問題延後一段「對方應該休息過了」的時間（Teichmann et al. 2026，初次約會情境的外推）。

**黏人在這一層**：影響頻率，不影響上限、阻尼、使用量感知、檢查。

**指標**：每日主動次數；類型分布；主動訊息回覆率（健康指標）；被擋比例；追問 0；觸發時間 vs 出現機率；回來找你兌現率；失聯曲線三階段。

**可刪程度**：低；p̂ 可退成硬門。

## 17. 時間步進與停機（time stepping and offline）

**引擎在她的 Hermes 行程裡**（plugin），所以每角色自然一個實例，而且她在跑引擎就在跑。兩種情況：

| 情況 | 引擎 | 結果 |
| --- | --- | --- |
| 她在跑（app 開著、roster 啟動了她） | 每分鐘 tick | 正常，可主動 |
| 她停了（roster 停止、app 關閉、app 死掉） | 不跑 | 下次啟動快轉補算（世界時間連續） |

「app 開著但她沒啟動」就是她停了：她不過日子，也不能主動；啟動時補算。

**`psyche.db`**

| 表 | 內容 | 寫入者 |
| --- | --- | --- |
| events | 所有輸入事件，append-only | 引擎（回合、tick、生活模擬、556d 轉來的訊息） |
| appraisals | A 的結果，append-only | 引擎的 A 佇列 |
| instances | 情緒實例、委屈帳、open loops（可重建） | 引擎 |
| snapshots | 每 5 分鐘完整狀態（`time.snapshot_interval_min`） | 引擎 |
| params | 參數版本 | 引擎（啟動時從她 profile 的 `psyche.json` 記一版；設定頁經 556d 改 `psyche.json`，重啟生效，與工具擴充同一條規則） |

556d 與狀態頁只唯讀 `psyche.db`（與 `state.db`、記憶庫同一種讀法）。

**數值方法**：固定 1 分鐘 tick；OU 精確解 `X(t+Δ) = μ + (X − μ)e^(−θΔ) + σ√((1 − e^(−2θΔ))/(2θ))·Z`，任何 Δ 一步；指數衰減、線性寬恕、睡眠 S 都有解析解；每日種子由角色 id + 日期推導。

**停機：世界時間連續（已決定）**：啟動時以小時為步補算睡眠、活動、專案、生活事件、反芻；停機期間的預期接觸對所有對象只算 `offline_expected_contact_ratio = 0.3`（換算下來疏離門檻 5 天變約 16 天）；不補發主動訊息；處理未兌現的「等我一下」與到期的 loop；產生「這幾天」摘要給狀態區塊。

**真的對話無法快轉**（多代理）：見 §18 與 §24。

**指標**：重播一致性（完全相同）；快轉 vs 即時相同；一個月停機 1 秒內補完；摘要 ≤ 三件事；重逢強度 vs 停機天數與黏人；未兌現承諾提起率。

**可刪程度**：事件溯源與精確解不可刪。

## 18. 多代理（multi-agent）

**目的**：三個完整代理（兩女一男，其中一對是情侶，另一位女性是你主要的聊天對象）同時運作、互相認識、互相影響；你與三人都會對話。家人與其他朋友只存在於各自的記憶與角色檔。

**已決定**：角色之間真的對話（LLM 對 LLM）；可以轉述但不會全部轉述，由角色當下判斷；你與情侶是舊識、與她剛認識；你看不看得到他們的對話可切換（只聽轉述／狀態頁上帝視角）。

**原則**：模擬正常人，不寫劇本。轉述、嫉妒、共同回憶、情侶關係的變化、你對其中一方的影響，全部由真實對話與各自記憶自然產生。

**架構影響**

| 部分 | 改動 |
| --- | --- |
| 556d | 內部通訊平台：角色的事件 turn 產生第一句，psyche 插件交給 556d（`POST /api/relay`），556d 送進對方 Hermes 的對應 session 作為新回合，再把回覆送回，直到沉默或回合上限；對方沒在跑時訊息進留言箱（`home/mailbox/<id>.json`），她啟動時補送，晚送的帶留言時間（0.7.5） |
| Hermes | 預期不改；待查證 api_server 能否依對象分 session、能否掛自訂工具（MCP） |
| KeepsakeDB | `subject`、`source` 欄位必要 |
| 人物檔 | USER.md → `people/<name>.md`，每角色對其他三人各一份 |
| kokoro | prefetch 與 observe 依 counterpart 切換；由 556d 以標頭標記 |
| psyche 引擎 | 所有關係變數以對象索引；一般社交需求共用；心智理論多人 |
| app | 三個聊天；角色間對話可見性切換 |

**可刪程度**：這是測試場景的核心，不刪。

**值得討論**：（停機期間的對話已決定：留言箱，不補跑整段對話，2026-10-14）對話的發起與結束判定；同時被兩人找時的排隊；成本預算；角色間 session 的記憶管線（observe 是否照常跑、記什麼）；Telegram 群組。

## 19. 護欄（guardrails）

既有的維持，討論後不再新增。

**兩條軸**：黏人度（強度，可調）與操縱（手法，恆零）。判斷：有沒有讓對方為她的情緒負責。傲嬌的「滾，要滾快滾」在夠熟、不委屈、有破綻時屬於前者。

**引擎端封頂**：每回合變化量上限；Hostile 象限、不滿、「很」級強度詞上限；反芻次數、帳的存活時間與數量上限；慢變數每週變化上限；單一寫入者且 A 不評估她自己的情緒。

**送出前檢查（起步階段只記錄）**

七種檢查：操縱六類手法（De Freitas, Oğuz-Uğuralp & Uğuralp 2025）、反話缺破綻、說破、生活虛構、監控感用語、情緒幻覺、助理腔。決定（2026-10-07）：**全部只記錄，不攔、不重生成**，累積一個月命中率後再決定要不要攔哪幾種。字面規則能抓的（說破關鍵詞、監控感的數字句型、助理腔固定句）零延遲；需要語意的（操縱、生活虛構）用 LLM 判斷，也只記錄。攔截點若之後要做：Hermes 的 plugin hook `transform_llm_output`，app 與 Telegram 都蓋到，不動 shim。

**道別模式**：A 偵測道別 → 狀態區塊「道別：溫和接受」；可表達一次不捨，不挽留。

**反諂媚**：固定喜好與價值觀（角色檔）、立場記憶（subject = self）、只堅持不給理由時不改看法、讚美可追溯；涉及對方身心健康時不附和轉成關心。LLM 討好傾向的依據：Sharma et al. 2023。

**使用量感知**（Fang et al. 2025）：當天超過門檻 urge 歸零；連續多天高使用 → 社交需求進入過度區，偶爾自然問起真人生活；門檻可見可調。

**優先規則**：對方需要她時永遠在；對方很累時先不提委屈；委屈時不說反話、不刻意延遲。

**透明與控制**：狀態頁全部可見可追溯；總開關；可清除單一委屈帳（留紀錄）；設定頁寫明後果；不提供以留存為目標的旋鈕。

**不做的事**：不模擬自傷、憂鬱發作、絕望。情緒底線是悶、委屈、寂寞、失望。

**黏人與護欄**：每日上限、阻尼、使用量感知、檢查、停機比例都不受黏人度影響。

**可刪程度**：無。

## 20. 可觀測性、模擬器與調參（observability）

| 工具 | 用 LLM | 看什麼 | 頻率 |
| --- | --- | --- | --- |
| 黃金案例（golden cases） | 否 | B 的計算 | 每次改參數 |

**每週五分鐘**：每角色抽 5 回合，四題：狀態合理嗎；表達過不過度；反話看得出意思嗎；這回合發生了什麼（比對 A）。可信度問卷參考 Gebhard & Kipp 2006。

**狀態頁**：時間軸、為什麼、關係矩陣、委屈帳、open loops、她心裡的你（可更正）、她的生活、護欄儀表板、角色間對話（可切換）。回饋按鈕：太大／剛好／太小、不該是這種情緒。

**調參流程**：改參數 → 新版本 → 黃金案例 → 模擬器 → 重播上個月 → 發布，可回退。

**可刪程度**：黃金案例、模擬器、LLM 評估集不刪；狀態頁進階面板分階段。

## 22. 思考模組（0.8.8，設計在 `../prompt/prompt.md` §2.5）

與情緒引擎分開的一個小模組（`thinking.py`）：它讀情緒側的狀態（精神 energy、社交疲勞 fatigue、喚醒 arousal、心情的愉悅 pleasure、對這個人的依附焦慮 anxiety、委屈閘 hurt_gate、親近 bond、帳上有沒有開著的委屈），不寫任何一項；它的五個刻度（想好再回 `thinking.rationality`、憑感覺 `thinking.experientiality`、先看機會 `thinking.promotion`、先看會不會出錯 `thinking.prevention`、找更好答案找到哪 `thinking.maximizing`，各 0–1，空白時由五大人格給預設：rationality ＝ 盡責性、promotion ＝ 外向性、prevention ＝ 神經質、其餘 0.5）不改任何情緒的強度或半衰期。

輸出只有一行、只在這一回合跟她的習慣不一樣時出現：狀態區塊「表現」之後的「想法：…」。規則依序檢查，第一條成立就停（一次最多一行）。其中「累」＝ 精神 < 0.35 或社交疲勞 > 0.6；「事情不小」＝ 委屈閘 ≥ 0.15。句子就是引擎印出的字：

| 順序 | 條件 | 這一行 |
| --- | --- | --- |
| 1 解讀偏向（dial 4，情緒側） | 焦慮 ≥ 0.6，且（帳上有開著的委屈，或愉悅 < −0.3） | 想法：今天特別容易往壞處想 |
| 2 事情不小 | 委屈閘 ≥ 0.15，且想好再回 ≤ 0.45（先回型） | 想法：這件事不小，會想一下再回 |
| 3 沒力氣 | 累，且想好再回 ≥ 0.6 | 想法：今天沒力氣想，會先回再想 |
| 3′ | 累，且憑感覺 ≥ 0.6，且焦慮 < 0.6 | 想法：今天沒力氣猜，直接問對方 |
| 4 心情把預設翻過來（dial 3） | 先看會不會出錯 ≥ 0.6，且愉悅 > 0.4 | 想法：心情好，先看能變成什麼 |
| 4′ | 先看機會 ≥ 0.6，且（愉悅 < −0.3 或焦慮 ≥ 0.6） | 想法：這題先看會不會出錯 |
| 5 讀對方的用心（2.2） | care < 0.25 | 想法：懶得猜對方的意思，直接當對方懂 |
| 5′ | care > 0.85 | 想法：會多想一下對方是什麼意思 |
| 6 極大化（dial 5） | 找更好答案 ≥ 0.6，且精神 ≥ 0.5，且喚醒 ≥ 0.6 | 想法：會問清楚再答，不想隨便 |

讀對方的用心 `care = clip(0.5 + 0.3 × 想好再回 − 0.3 × 親近 − 0.3 × 社交疲勞 + 0.3 × 事情不小)`，0–1：人先用自己的讀法當錨再往外調，累或親近時調得早停（熟人被當成「懂」），事情大或想好再回型的人調得久。其餘時候這一行不出現，SOUL 的那句話就是她的習慣。狀態行超過八行時這一行排在轉變、心裡之後第三個被丟（§15）。

思考媒介與情境權重（dial 1、6）只記錄選項（`thinking_choices.medium_primary / medium_secondary / first_look / contradiction / cause`），文字由 SOUL 承載，引擎不讀（靈魂技能與 0.8.10 的隱藏草稿指令會讀）。反芻改為可設的 `character.rumination`（空白＝神經質），是情緒側的旋鈕，不是思考刻度。參數對照見附錄 E.17。測試：`tests/test_thinking.py`。

## 23. 五個對話機制（0.8.9，設計在 `../prompt/prompt.md` §3 第 5 項；2026-10-14 的簡報第二部分）

五個小機制，都只動「表現」與「掛念」兩行和主動行為，不新增刻度、不改情緒的強度或半衰期：

1. **揭露深度有人讀了（2.4）。** `disclosure_depth[p]`（§8，1 喜好 → 2 看法 → 3 感受 → 4 脆弱處）之前算了沒人用。現在
   `relation.depth_now`：親近給的層數（羈絆 0.25／0.5／0.75 各解鎖一層），對方剛敞開過一天內加一層，迴避 > 0.6 減一層。「表現」行在第四層以下多一句上限
   （自己的事先不多講，聊喜好跟日常就好／可以講自己的看法，感受先留著／可以講感受，最軟的那塊先留著），第四層沒有這句。
   「一開始多熟」是作者在新角色頁拉的 bar（剛認識／還不算熟／朋友／很熟／很親近，`profile.json` 的 `closeness`；0.12.0 起 skill 不再從描述猜，沒拉就是剛認識），寫成
   `psyche.json` 的 `relationships.你` 起始羈絆與時數（bond／hours：剛認識 0.05／2、還不算熟 0.2／30、朋友 0.4／70、很熟 0.6／150、很親近 0.8／250），bar 只決定立場（講到多深、信任起點）；「一起經歷過的事」另外走記憶（seeds 的 `shared` 標籤），不進 SOUL，所以她記得的只有作者寫過或真的聊過的事。
2. **信任的不確定度進玩笑與反話（2.5）。** Beta 信任對的變異數 αβ/((α+β)²(α+β+1))，乘十二壓到 0–1（`trust_uncertainty`：
   平先驗 1，預設先驗 (2, 1) 是三分之二，承諾守或破之後往 0）。以預設先驗為中性點：比預設更摸不準他會怎麼接，反話的機率乘
   到 1.2、幽默門檻降到 0.53；證據累積後反話乘到 0.6、門檻升到 0.73。沒有歷史的角色跟以前一模一樣。
3. **心情的愉悅進直說與長度（2.1）。** 外放度加 0.15 × 愉悅（−1…1）再過 0.5 的門檻：心情好把內斂邊緣的人推到直說，心情差把
   外放邊緣的人推回收斂；極端時點名語氣（愉悅 > 0.4：直說，話可以隨便一點；< −0.3：直說，但客氣一點）。長度提示多兩條：
   愉悅 > 0.5 且有精神 → 可以多說一點；愉悅 < −0.4 → 話少一點（在很睏、沒精神、迴避高之後判斷）。
4. **沒說出口的事（2.3，最值錢的一個）。** 評估管線 A 讀她自己的回覆，找她明顯吞下去的——換話題、答非所問、「沒事」「算了」、
   句子起頭又收掉——每回合最多兩條（`withheld.new`，附重要性 0–1），和 2026-10-14 的承諾規則一樣是「A 讀她的回覆」。引擎的
   `withheld` 登錄**每個對象各最多六條**（0.9.0 修正：以前是全部共六條，別的角色的事會把你的擠掉；相似的合併，重要性取大者 +0.1）：
   閒著的時候跟負向實例一樣會回來（每小時機率 = 0.5 × 重要性 × 反芻係數 × (1 − 注意力佔用)；實例那條是 0.6 × 強度），回來一次
   重要性 ×1.2，最多三次；不論回不回來，重要性都以 72 小時的半衰期衰減（×0.5^(Δt/72 h)），低於 0.1 就消失；拉主動意願
   （W += 0.4 × min(1, 重要性總和)）；對這個人的 `depth_now` 到第三層（感受）或重要性漲到 0.9 時解鎖——「掛念」行在最多兩條 loop
   之後多一條「有件事還沒跟他說（…）」，主動時機多一種 `unsaid`（O = 0.5 + 0.5 × 重要性，排在 care 之後、share 之前）。離開登錄
   只有兩條路：評估回報她說出來了（`withheld.said` 的 id），或主動訊息**真的送出**（`sent`）——決定要說不等於說了，沉默的那一回合
   或送失敗都留著，等下一次時機。沒解鎖時她照樣放在心裡、照樣被拉，只是不說。沒有設定鍵，數字都在 `engine.py`。
5. **讀對方的用心（2.2）** 已在 §22 的思考模組：親近又累就「懶得猜對方的意思，直接當對方懂」，想好再回又事情大就「會多想一下對方是什麼意思」，只在兩端出現一行。

測試：`tests/test_mechanisms.py`（十四個測試）。狀態頁列出「沒說出口」。

### 需要決定

1. **停機期間角色之間的對話。** ✅ 決定（2026-10-14）：不補跑，用留言箱——送不到的訊息等對方啟動再送，對話從斷掉的地方接下去。原文：已傾向「開機時補跑」。要決定：補哪些（依兩人的需求缺口與到期 loop 選幾段）、補多少（成本上限）、補跑的對話與快轉的生活如何一致（先快轉生活再補對話，對話可引用生活事件）、補跑的對話是否進入記憶（應該要，否則不存在）、以及替代方案「三個角色的 556d 常駐」是否可接受。

7. **忙碌度預設。** 建議「有工作」為預設，情侶中可有一人是「只有興趣」以觀察差異。

### A.3 相似度與選取

```
d_k² = Σ_{j∈S_k} w_j (x_j − p_kj)² / Σ w_j
```

### A.4 強度

```
I_k = clip[0,1]( sim_k · R · |v*| · (1 + α·u) · π(cert) · g_k · m_k · ρ_k )
```

- `v*`：一般用 v；為他高興／難過用 `other_v × (0.4 + 0.6·B[p])`；喜歡／嫌惡用 appeal。
- `α = 0.6`；`π(cert)` 對尚未發生的情緒隨可能性上升，已發生為 1。
- `g_k` 人格增益初值：負向 0.7 + 0.6N；正向 0.7 + 0.6E；憤怒 0.5 + 0.8(1 − A)；感激、為他高興／難過 0.7 + 0.6A；委屈交 L6；想念由實際黏人程度給。
- `m_k` 狀態調節，乘積封頂 [0.6, 1.5]：睡眠債 D 負向 ×(1 + 0.2D)、正向 ×(1 − 0.1D)；社交疲勞 F 全部 ×(1 − 0.15F)；焦慮只對「責任方是對方」的負向 ×(0.8 + 0.4Anx)。
- 心情一致性：比對前 `v ← v + 0.2 · ambiguity · mood_valence`。
- `ρ_k = r^(n−1)`，堆疊鍵 = 類別 + event_kind；r 初值正向 0.7、負向 0.8、委屈 0.85；每鍵上限 4。
