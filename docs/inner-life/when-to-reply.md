# 回不回：不是每則訊息都要回

最後確認：2026-11-16（已實作：`plugins/psyche/replying.py`、psyche 的 hooks、556d `transcript.go` / `chat.go`、app 的聊天頁）。決定紀錄在 `../DECISIONS.md`（2026-11-16）。

## 1. 問題

真人聊天時，很多訊息不需要回：「好啦 妳上班也加油」、對話尾巴的一個 😆、對方說「等我一下」之後回的 👍。
角色每則都回，所以對話收不了尾，而且會打破自己說過的話。2026-11-13 的 Telegram 實測：

- 角色甲：「好啦 妳上班也加油」→ 回了一句；接著一個 😆 → 又回一句。兩則都是收尾，真人多半不回，或按個表情就好。
- 角色乙：先說「手上有點忙，等我一下，晚點回你」；對方回 👍 → 他馬上回「我剛弄到一個段落，怎麼了」，自己說的「等我一下」就不算數了。

原因不是模型判斷錯，是她從來不知道「不回」是一個選項。

## 2. 現在已經有的

| 東西 | 在哪 | 現況 |
| --- | --- | --- |
| 不送出的標記 | Hermes `gateway/response_filters.py` | 整則回覆剛好是 `NO_REPLY`、`[SILENT]`（或 `SILENT`、`NO REPLY`）時，gateway 不送出，這一回合照樣存進對話。只有 cron 的 prompt 教過模型這個標記；聊天回合沒有任何地方提到。 |
| 按表情 | Hermes Telegram adapter `set_message_reaction`；`send_message(action="react")` 工具 | Telegram 做得到。但我們在 Telegram 上不給她工具（`platform_toolsets.telegram: []`），而且 `send_message` 能送到任何對話，給她太多了。 |
| 她自己決定不開口 | psyche `events.is_silence`、`on_event_reply` | 只用在她自己的事件 turn（主動訊息）：可以決定不說，記成 `silent`。對方傳來的訊息沒有這個選項。 |
| 「等我一下」 | psyche 狀態區塊「表現」行 | 工作中會提示「可以回短一點或說等她一下，忙完會回來找他」。但下一則訊息進來時，她還是每則都回。 |
| app 的聊天 | 556d ↔ 她的 API（api_server） | 上面那個過濾只在 gateway（Telegram）；app 這條路徑還沒處理標記，`NO_REPLY` 可能會被當成文字顯示。 |

## 3. 設計：一套共通規則

所有角色用**同一套規則**，由 psyche 每回合放進狀態區塊。不寫進 SOUL：SOUL 是她是誰，回不回是機制和當下的狀態。

### 3.1 兩種「不用文字回」

1. **不回**：整則回覆只寫 `NO_REPLY`。Telegram 不送；app 不顯示；這一回合留在對話紀錄裡，所以下次對方再傳，她知道自己上一則沒回。
2. **按個表情**：整則回覆只寫 `[REACT 🤣]`（一個表情）。我們的程式把它變成對方那則訊息上的 reaction：Telegram 用 `set_message_reaction`，app 顯示在你的訊息泡泡上（state.db 已經有 `set_message_reaction` 可存）。不給她工具。
   Telegram 只接受固定的一組 reaction 表情；不在清單裡的換成最接近的（例如 😂 → 🤣），換不到就當作不回。

一則回覆只能是其中一種，或是正常的文字。標記和文字混在一起時，當作文字送出，標記拿掉。

### 3.2 規則（狀態區塊的一行，所有角色一樣）

大意如下（實際字句實作時定，放在 psyche）：

> 不是每則都要回。對方只是在收尾（好啦、晚安、謝謝、單一個表情或貼圖），沒問妳什麼、沒帶情緒也沒帶新的事時，可以不回（只寫 NO_REPLY），或只按個表情（只寫 [REACT 表情]）。
> 有問題、有情緒、有新消息、或妳答應過要回的，一定要回。

護欄（寫在規則裡，也寫成測試）：

- 有問句、有情緒（難過、生氣、開心分享）、有新資訊 → 一定用文字回。
- 她自己丟了問題、對方剛回答 → 要回。
- 連續兩則都沒用文字回之後，對方再傳一則有內容的 → 一定回。

### 3.3 傾向：同一個公式，從現有的數字算

規則一樣，但「多容易放掉」每個人、每個時刻不同。不新增設定，從 psyche 已經有的東西算，變成狀態區塊裡的一句提示：

- **性格**（psyche.json 的 big5）：外向、親和高 → 比較常接話；內向、低親和 → 比較常放掉。
- **當下狀態**：在忙、累、心情差 → 比較常放掉；跟對方很親、心情好、想找他（需求缺口大）→ 比較常接一句。

例：「她在忙，收尾的訊息多半不回」「她現在想聊，收尾也可能接一句」。公式對所有角色一樣，差別只來自各自的數字。

### 3.4 記下來

- psyche 的 `turn` 事件多兩個欄位：`answer`（`silent` 或 `react`）與 `reaction`（表情）。沿用 `turn` 而不是新的事件種類，重播不用改。
- 評估管線 A、最近幾輪的紀錄與 kokoro 看到的她的回覆是「（沒回）」或「（沒回字，按了 🤣）」，不是標記本身。
- 她的對話紀錄裡那一列是 `NO_REPLY`，所以下一回合她知道上一則沒用文字回；連續兩則沒回之後，「回不回」那行會改成「這則有內容就回」。
- 表情由 psyche 的 `transform_llm_output` 處理：把 `[REACT x]` 換成 `NO_REPLY`，等 Hermes 存好你那則訊息後，把表情寫進那一列的 `display_metadata`（author `agent`），Telegram 來的訊息另外用 Bot API `setMessageReaction` 按上去（不經過 gateway 的事件迴圈）。
- 只在她的模型不串流時成立（`model.streaming: false`，目前的設定）；串流時標記可能在 hook 之前就被送出。

### 3.5 app

- `NO_REPLY` 的回合不顯示泡泡、不鏡像到 Telegram、不出現在角色頭上的對話框（556d 的歷史與即時兩條路都一樣）。
- 表情顯示在你那則訊息的左下角：歷史讀 `reaction` 欄位，即時由 556d 等表情寫進去之後送 `chat.reaction`（最多等約 25 秒）。

### 3.6 測試

兩個方向都要測：

- 收尾（好啦、晚安、單一表情、「等我一下」之後的 👍）→ 多半不回或按表情。
- 問題、情緒、新消息 → 一律有文字。
- 標記：只有標記才算；標記混文字 → 送文字；不支援的表情 → 換或不回。
- app 與 Telegram 顯示一致。

## 4. 這一版不做

- **「晚點回你」的兌現**：她說了等一下、還在忙，就先不回；忙完自己回來找對方。psyche 已有主動類型「回來找你」（`return_promise`，§16），可以接上，但要記住「我欠他一則回覆」和忙碌時段的結束時間，是另一個機制。這一版靠 3.3 的「在忙 → 多半不回」先擋住大部分。
- **每個角色自己的設定值**：見下一節。

## 5. 未來：把「個性」做成每個角色自己的

這一版的回不回，和現在大部分的行為（回覆長度、何時說「等我一下」、表情用多少、主動訊息多頻繁）一樣，都是**共通規則 + 從性格數字推出來**。
角色之間的差別只來自 big5 等幾個數字和 SOUL 的文字。

之後可能想把這些做成每個角色真正自己的：例如某個角色就是幾乎每則都回、另一個常常已讀不回、某個愛按表情。做法可能是 psyche.json 裡的覆寫值（確認頁的進階），蓋過推出來的傾向。

這是之前沒想過的一塊，難處不在加欄位，而在**調**：

- 一個角色建好之後，要實際跟她聊一陣子，才看得出哪裡不像她，再回頭調數字；等於每個角色建好後還要逐一調她的 Hermes 與 psyche。
- 需要一個「建好之後的調整」流程：看紀錄（狀態頁、事件）→ 找出不像的行為 → 改哪個數字 → 重開驗證。現在的新角色流程到「產生 → 確認 → 安裝」就結束了，沒有這一段。
- 哪些行為值得開放成個人值、哪些維持共通規則，要先用共通版測一段時間再決定。

所以先用共通規則測，把「個人化的個性」和「建好後的調整流程」一起當成未來的工作。
